### Check that the tests can go green

To rule out a broken helper, I copied the repo to a throwaway directory outside the working tree, added a minimal `retryRejected` and `retry-<index>` button there, and ran the suite: 39 of 39 passed and `tsc --noEmit` was clean. I then broke that copy in 14 ways (no persist, moved to end of list, reason kept, attempts reset, no status check, store rewritten on refusal, retry shown on every / pending / synced entry, no sync after an online retry, sync after an offline retry, new id on retry, send before persist, throw instead of an error value); each one made at least one new test fail. The copy is deleted and none of it is in the commit or in `src/`.

### Choices the issue did not decide

- **`retry-<index>`** is read as the entry's list position, the same index as `entry-<index>`.
- **Result shape**: the tests assert only `result.ok` (`true` or `false`). The success value and the error text are not pinned.
- **Decisions from RAU-5 are tested under REQ-DRILL-010** (reason cleared, attempts kept, sent by the normal flush, online retry starts a sync, offline retry waits), since they have no requirement ID of their own.
- **Tests 12 and 13 cite two IDs** (`[REQ-DRILL-012] [REQ-DRILL-010]`) because they drive a retry through the screen. `specs/TRACE.md` therefore lists the component file under REQ-DRILL-010 as well.
- **Test 13 asserts that an offline retry sends nothing.** RAU-5 says the drill "waits like any other pending drill"; I read that as "the screen starts no sync". If a harmless flush attempt while offline is acceptable, that one assertion (`expect(gateway.sends).toBe(1)`) is stricter than intended and a person should say so.
- **Test 11 puts the positive check first.** With no retry control anywhere, "offers none for pending or synchronised" holds trivially today, so that half of REQ-DRILL-012 cannot be shown failing on its own. The mutation check above is the evidence that it bites once the control exists.

### Not claimed

- These tests do not show that the feature works: no implementation exists, and the throwaway implementation was mine, not the one RAU-7 and RAU-8 will deliver.
- `npm run trace` reports 15 of 15 covered while 14 tests fail. The gate checks that an ID is cited, not that the citing test passes.
- "Persisted before any network call" is checked against the in-memory test store and by reloading a second queue on it. Real AsyncStorage, a crash between the status change and the write, and a storage write that fails are not exercised.
- A retry requested while a flush is in flight, and two retries of the same drill at once, are not tested.
- The offline "nothing is sent" check reads the send count right after the screen shows `pending`; a send started later than that would not be caught.
- Only the control's presence, absence and press are tested. Its label, accessibility role, placement and what the screen shows when a retry is refused are not.
- No gateway, Firestore rules or end-to-end (Maestro) coverage was added for the retry; REQ-DRILL-005/006 idempotency after a retry rests on the existing tests.
- `npm run test:rules` and the Maestro flows were not run; CI has not run on this commit.
